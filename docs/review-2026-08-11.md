## Part 1 — Functional review

**Baseline:** all three CI steps pass locally — `npm run typecheck` clean,
`npm test` 10/10 in 0.8 s, `npm run build` succeeds (156 kB JS, 50 kB gzipped).
CI runs the same three on push and PR.

### What works

The whole data path works end to end against the real store:

```
GET /            -> 200
proxy sessions   -> 200      87 sessions
proxy llm-calls  -> 200
SSE live tail    -> ": connected" then real job.started frames
```

Sessions carry what the README promises — `hoglah` 206 events, `s1` 1 541
events across `codex, feedback, tirzah`, and so on. The Vite proxy correctly
fronts `galeed serve` on :8785.

Three things are notably well done:

- **Error and empty states are exhaustive.** `SessionDetail` distinguishes five
  distinct conditions — load error, stream interrupted, loading, no events for
  this session, and no events matching the current filter. Most viewers collapse
  the last two into one blank panel. The SSE handler surfaces a reconnect hint
  rather than letting a dropped tail go silently stale, with the reason in a
  comment citing the issue it closed.
- **The dependency surface is two packages.** `react` and `react-dom`, nothing
  else at runtime. For a viewer that renders untrusted captured text, that is
  the right instinct.
- **The security note is honest and specific.** It says plainly that the LLM
  Calls view renders complete prompts and outputs including retrieved memory,
  that the backing APIs are unauthenticated and localhost-bound, and not to
  proxy them further. That is a more useful warning than most projects manage.

### Functional defects

#### F1. A cyclic `parent_call_id` makes calls vanish from the debugging view — **FIXED**

`buildForest` attaches each node to its parent and treats the rest as roots. If
two calls reference each other, neither is a root and neither is reachable:

```
buildForest([ {call_id:'a', parent_call_id:'b'},
              {call_id:'b', parent_call_id:'a'} ])
  => roots: []      // both calls disappear entirely
```

Nothing is logged and nothing is rendered. For a tool whose purpose is showing
what actually happened, silently dropping records is the worst available failure
mode — the operator concludes the calls were never made.

An orphaned `parent_call_id` (parent outside the fetched batch) is handled
correctly and becomes a root, so only the cyclic case is affected.

#### F2. Duplicate `call_id` silently discards a call — **FIXED**

```
buildForest([ {call_id:'dup', prompt:'first'},
              {call_id:'dup', prompt:'second'} ])
  => 1 root, prompt = 'second'      // 'first' is gone
```

`byId.set(call.call_id, …)` overwrites. `call_id` uniqueness is an assumption
about every emitter across the family, not something Mizpah can verify — Hoglah
uses its job id, and a collision or a re-emitted record costs a call from the
view with no indication.

#### F3. `sortEvents` compares timestamps as strings — **FIXED**

The comparison is `a.timestamp < b.timestamp`, which is chronological only when
every emitter uses byte-identical formatting. Two proven inversions:

```
fractional vs whole second in the same second:
  input:  later='…T09:00:00.500000+00:00', earlier='…T09:00:00Z'
  actual: [ 'later', 'earlier' ]        // wrong order

non-UTC offset vs Z:
  input:  first='…T09:00:00+01:00' (08:00Z), second='…T08:30:00Z'
  actual: [ 'second', 'first' ]          // wrong order
```

**This is latent, not live.** Every emitter in the store currently agrees:

```
timestamp shapes across 4 000 live events:
  4000  frac/+00:00
  tirzah 2092 · codex 1762 · feedback 84 · hoglah 52 · milcah 9 · mahalath 1
```

So today the ordering is correct by convention. The risk is that the convention
is undocumented and unenforced — Galeed's `SCHEMA_VERSION` says nothing about
timestamp format, and (per the Galeed review) is not checked on read anyway. A
seventh emitter using `Z`, or dropping microseconds, reorders a timeline with no
error.

Related: because microsecond timestamps are never exactly equal, the `seq`
tiebreaker on the line above is effectively dead code.

#### F4. The timestamp column makes the same format assumption — **FIXED**

`event.timestamp?.slice(11, 23)` renders the time column by character offset. It
produces `08:17:12.259` on the current format and something meaningless on any
other. Same latent coupling as F3, in the view layer.

## Part 2 — Code review

### Medium

#### M1 · `CallsView.tsx:17-27` — `buildForest` has no cycle guard — **FIXED**

Code side of F1/F2. The `parent !== node` check catches a direct self-parent but
not a two-node cycle or anything longer.

**Fix:** walk the ancestry when attaching (bounded by the node count), and treat
a node whose chain revisits itself as a root, ideally flagged in the UI. Detect
a duplicate `call_id` on insert and keep both, suffixing or grouping — a
debugging view should over-report rather than under-report.

#### M2 · `CallsView.tsx:29-41` — `matches` requires a pre-lowercased needle — **FIXED**

```
matches(call({output: 'The Watchtower'}), 'watchtower') -> true
matches(call({output: 'The Watchtower'}), 'Watchtower') -> false
```

The haystack is lowercased, the needle is not. The UI caller does
`search.trim().toLowerCase()` first, so the app is correct — but `matches` is
exported, unit-tested and reusable, with an undocumented precondition that fails
silently. `callsLogic.test.ts` only ever passes lowercase needles, so the test
confirms the implementation's assumption rather than the function's contract.

**Fix:** lowercase the needle inside, or rename to `matchesLowercased`.

#### M3 · `traceLogic.ts:79-91` — `negotiationPhaseLabel` falls back to free text — **PARTLY FIXED**

```
metadata.note = 'unrelated commentary'  ->  label: 'unrelated commentary'
```

The chain is `negotiation_phase` → `note` → regex on the summary → `'pre-plan'`.
`note` is a general-purpose field, so any emitter that puts prose there gets it
rendered as a phase chip. The final `'pre-plan'` default also asserts a phase for
an event that declared none.

**Fix:** only accept `note` when it matches the known phase vocabulary; return
`null` rather than defaulting when nothing is declared.

**Actioned, and half of this was wrong.** The vocabulary constraint is in — free
text in `note` is no longer rendered as a phase. The `'pre-plan'` default was
*kept*: on inspection it is not a fabrication but a domain fact, since in
Deborah's slice negotiation is pre-plan unless explicitly marked
`post_retrieve`, so removing it would have lost a real distinction the view was
making. There are no negotiation events in the live store yet to settle it
empirically, and the chips are in-progress uncommitted work, so changing a
default out from under it would have been the wrong call. Revisit if an emitter
ever labels pre-plan explicitly.

#### M4 · `traceLogic.ts:94-107` — chips stringify whatever metadata holds — **FIXED**

```
metadata: { negotiation_status: {nested: 'object'}, evidence_count: 3, novel_detected: true }
  -> chips: [ 'pre-plan', '[object Object]', 'ev=3', 'novel' ]
```

`String(meta.negotiation_status)` renders `[object Object]` for a non-scalar.
Separately, `SessionDetail.tsx:122` uses `key={c}` — the chip string itself — so
two chips with the same text (a status of `agreed` alongside a phase of
`agreed`) produce duplicate React keys.

**Fix:** skip non-scalar values (or `JSON.stringify` them), and key by index.

#### M5 · `App.tsx:72-76` — the live tail re-sorts the whole array per event — **FIXED**

```ts
setEvents((prev) =>
  prev.some((existing) => existing.event_id === event.event_id)
    ? prev
    : sortEvents([...prev, event]))
```

Each arriving frame does an O(n) duplicate scan, an O(n) copy and an O(n log n)
sort. On the `s1` session (1 541 events) that is meaningful work per frame, and
the cost grows as the tail runs. Events arrive in order in practice, so the sort
is almost always a no-op that still pays full price.

**Fix:** insert at the correct position (usually the end) rather than re-sorting,
and keep a `Set` of seen `event_id`s for the duplicate check.

### Low

#### L1 · `SessionDetail.tsx:56-58` — copy silently does nothing when unavailable — **FIXED**

`void navigator.clipboard?.writeText(...)` — the optional chain means that in a
non-secure context (the app served over plain http from another host) the button
does nothing and says nothing. Worth a one-line failure hint, in a UI that is
otherwise careful about surfacing states.

#### L2 · `callsLogic.test.ts` lives beside the module it does not contain — **FIXED**

`buildForest` and `matches` are exported from `components/CallsView.tsx` — a
component file — and tested from `src/callsLogic.test.ts`, a name that implies a
`callsLogic.ts` module that does not exist. `traceLogic.ts` is the pattern that
works. Moving the two pure functions there would match it and keep the component
file about rendering.

## Comparison with the other estate reviews

Mizpah is the smallest thing reviewed (1 394 lines including CSS) and, per line,
the most careful about *telling the operator what is going on* — five distinct
empty/error states, a reconnect hint on a dropped tail, an honest security note.
That is the quality the other reviews kept asking for.

Which makes its defects the more pointed, because they are all the same shape and
it is the estate's recurring one: **silence**. A cyclic parent makes calls vanish
(F1). A duplicate id discards one (F2). An uppercase needle matches nothing (M2).
A non-scalar renders as `[object Object]` (M4). A clipboard failure does nothing
(L1). None logs, warns, or shows a placeholder.

That matters more here than elsewhere. Mizpah is the **watchtower** — the thing
you look at to find out what happened. Every other tool in the family can afford
to drop a record quietly; the viewer over those records is the one place where a
silent omission is indistinguishable from the event never having occurred.

The F3 timestamp coupling is the other estate pattern in miniature: an
undocumented convention holding across six repos with nothing enforcing it,
which the Galeed review already flagged from the other end (`SCHEMA_VERSION` is
written and never read).

## Suggested order

1. **M1** — cycle guard and duplicate-id handling in `buildForest`. The only
   findings that lose data outright, in the view whose job is not losing it.
2. **M2** — lowercase inside `matches`, and add an uppercase case to the test.
3. **M4** — non-scalar chips and the duplicate React key.
4. **M5** — insert instead of re-sort on the live tail.
5. **M3** — constrain the `note` fallback to the known phase vocabulary.
6. **F3/F4** — either normalise timestamps to epoch on ingest into the client,
   or get the format written down in Galeed's schema contract so the convention
   is enforced rather than assumed.
7. **L1, L2** — small.

Nothing here is architectural. The API boundary is clean, the component split is
sensible, the pure logic is genuinely separated and tested, and the whole thing
builds to 50 kB gzipped with two dependencies.
